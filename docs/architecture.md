# alphakit 架构

中低频 Alpha 研究与回测系统。美股，日频。

这份文档讲**系统长什么样、为什么这么长**。精确到可以照着实现的规格在
[`implementation.md`](implementation.md)；数据契约在 [`l2_schema.md`](l2_schema.md)；
怎么用在 [`manual.md`](manual.md)；尚未实现的部分在 [`roadmap.md`](roadmap.md)。

---

## 1. 系统要解决的问题

研究员写一个想法，希望知道它值不值钱。中间横着一堆本该由基础设施承担、实际却
反复落到每个人头上的事：取数、对齐、防前视、成本、容量、可比性。

这套系统的立场是：**把这些收进引擎，让研究员写的东西缩到只剩想法本身**。
`repos/g_yliu/nodes/alpha_yliu_rev/rev.py` 的全部内容是：

```python
def handle(ctx):
    n   = ctx.params["window"]
    px  = ctx.win(PX, n + 1)
    raw = -(px.loc[0] / px.loc[-n] - 1)     # 反转: 跌得多的买
    return raw / ctx.f(RVOL)                 # 波动归一
```

没有日期参数、没有循环、没有对齐、没有 NaN 处理、没有池子掩码。这四行之外的一切
——预热多少天、池外怎么办、权重怎么归一、成本怎么算、哪天停牌——都由引擎按**写死的
口径**处理，而不是由每个人各写一遍。

## 2. 三层数据，一道单向边界

```
L1  厂商原始载荷            storage/data/base/l1/     只落地, 不改写
     ↓  pipeline/build_l2.py                          复权反演在这一步做完
L2  交付层, 管道分隔纯文本   storage/data/base/l2/     五张表, 逐交易日 PIT
     ↓  pipeline/build_l3_base.py                     一次性
L3  派生层, Zarr 数组        storage/l3/{region}/      **引擎唯一的输入与输出**
     ↓  run / pnl
```

**引擎只认 L3。** 它不认识 L2，更不认识任何厂商格式。这道边界的价值有两层：

- L2 的已知缺陷（无 vwap、`adj_factor` 非 PIT、生存者偏差）**挡在引擎之外**，
  被记进 `known_defects` 随指标一起走，而不是在引擎里到处打补丁；
- L3 的形状只有三种（下节），于是逐日主循环、掩码、仿真器都只需面对这三种，
  不必为每个数据源分叉。

L3 **完全可重建**——给定 L2 与 `repos/` 里的代码，整个 `storage/l3/` 删掉重来约 8 秒。
它入库只是为了开箱即用。

## 3. 一切都是 Node

**这是整套系统最核心的一个判断：数据字段与 alpha 不是两种东西。**

`field_base_px`（收盘价）、`factor_yliu_liq`（流动性因子）、`alpha_yliu_rev`（反转 alpha）
走的是**同一个内核、同一条命令、同一套契约**：

```
一个 yaml（声明接线） + 一个 py（只写数学）  →  run  →  L3 数组
```

| | 数据字段 | 因子 | alpha |
|---|---|---|---|
| 谁写 | infra | 研究员 | 研究员 |
| yaml + py | ✓ | ✓ | ✓ |
| 落进 L3 | ✓ | ✓ | ✓ |
| 唯一的差别 | — | — | 声明了 `universe`、ops 链以 `scale` 收尾 |

统一的收益不是省代码，是**口径统一**：因子的池外掩码与 alpha 的池外掩码是同一行代码，
不会因为"这个是数据、那个是信号"而悄悄不一样。alpha 之所以能被别的 alpha 当输入
（combo），也正因为它就是一个普通节点。

### 名字即身份

节点名 `{kind}_{ns}_{name}` 是唯一的 identity，`kind` 与 `ns` 从中**解析**而来，
不在 yaml 里另行声明——少一处可以写错、也少一处可以与目录打架的地方。

引用名与磁盘路径是**纯字符串的一一对应**，不需要任何索引就能互推：

```
g_common.field_base_px.adj_close_1500
   ↕
storage/l3/us/g_common/field_base_px/adj_close_1500/
```

没有 catalog 文件、没有数据库、没有 ID 表。`store.catalog()` 是扫目录现算的。
这让"库"永远不会与"索引"不一致——因为没有索引。

## 4. 三种秩，di 恒为第一轴

L3 不是恒为 `date × instrument`。节点自己声明秩：

| dims | 形状 | 用途 |
|---|---|---|
| `[di]` | `(D,)` | 每个 session 一个标量（市场收益、无风险利率） |
| `[di, ii]` | `(D, N)` | 日频截面，绝大多数节点 |
| `[di, ii, ti]` | `(D, N, T)` | 日内网格（5 分钟槽位） |

**`di` 必须是第一轴，且分块沿 `di` 切**——否则日更要重写全部历史，O(1) 追加不成立。
秩-3 取 `(1, N, T)` 一天一块，是同一条理由的极端情形：日更只写一个文件。

轴（交易日列表、`security_id` 列表）**全局共享、append-only**。chunk 里存的是
**位置**不是名字，所以往轴中间插一天等于让全库面板整体错开一天——一次性给每个
alpha 注入一天前视，且形状不变、指纹不动、无人报警。故它是一道硬闸门。

## 5. 逐日游标：防前视靠构造，不靠自觉

引擎按 session **逐日推进**，handle 每次只拿到"当日那一片"：

```python
ctx.f(ref)         # 当日截面
ctx.win(ref, w)    # (w, N) 窗口, 行标签 -(w-1)…0, 0 = 当前处理日
```

**没有日期参数、没有绝对索引、没有 store 写句柄。** 研究员**拿不到**未来的数据，
不是因为规范禁止，而是因为 API 里没有那个东西。防前视的证明义务因此从"审查每个人的
代码"缩成"审查 ctx 的 API 面"。

代价是要为逐日循环付性能——实测没有：2000 天 × 6000 标的的 20 日均值，逐日循环
235 ms，一次性向量化 713 ms。逐日只在窗口上做增量更新，向量化要物化整张中间表。

### 两道掩码闸门

池子（universe）在**两端**各夹一次：

```
ops 之前：当日池外的列整列 NaN     → 截面统计天然限定池内, 非 skipna 的写法立刻得到 NaN 报警
scale 之后：池外权重恰为 0          → 账本里不会有池外仓位
```

只做一端两条承诺不能同时成立：TS 算子会把昨天的值搬到今天，那只票今天若已出池，
它的权重会先进分母再被抹掉，`Σ|w|` 就悄悄小于 1——**账本只投出去一半而 Sharpe
看着完全正常**（实测三个 alpha 混合后 `Σ|w|` 只剩 0.51）。

## 6. 指纹：定义变了就拒绝写入

同一个名字下，改一行公式再跑日更，数组里改动日之前是定义 A、之后是定义 B，且
**无从察觉**。所以每次写入前比对指纹（yaml 子树 + 代码字节 + 依赖 + universe + lookback），
不符即拒绝，要改就显式 `--rebuild` 并 bump version。

闸门放在 `store.write` 里而不是 runner 里——ingestion 脚本也要过，而那正是最容易
悄悄改一行公式的地方。

---

## 7. region：可比性的锚

`repos/{repo}/regions/{region}.yaml` 声明整个团队共用的口径：日历、cutoff、
return_metric、booksize、成本、参与率、停牌降级。每个 repo 各存一份，**内容必须一致**；
规范化后的 hash 进权重 meta，评估时比对。

**自由研究、统一提交**：研究期你可以改自己那份去试，但只要 hash 与别人的对不上，
指标就被标成不可比——而不是让两个人拿着不同口径算出的 Sharpe 互相比较。

路径键（`l3_root` / `pnl_out`）**不进 hash**：它回答的是"你我用的是同一套口径吗"，
不是"你我的磁盘长得一样吗"。

## 8. 评估：单值账本的 precise 仿真

不记股数，只记**市值**，逐日推进：

```
持仓推进 → 冻结重分配（停牌/退市的仓位不可动, 其余重新瞄准）
        → 目标 = 权重 × booksize → 参与率截断 → 成交 → 计成本
```

关键判断是**不记股数**：股数需要复权价与拆股处理，而复权本身是 L2 的事；市值账本
让拆股在推进式里自然抵消（拆股日持仓价值连续、pnl = 0），不需要引擎再处理一次公司行动。

### NaN 的三分类

`ret` 是 NaN 时必须分清三种情况，因为它们的账务处理完全不同：

| | 判据 | 处理 |
|---|---|---|
| 退市 | `delist_date` | 按最终对价计损益后清仓，资金回收 |
| 停牌 | `is_halted`（或降级：连续 K 日 NaN） | 仓位原地冻结，跳空损益落在复牌日 |
| **幽灵** | 两者都不是 | **报警**；少量按最后可得价平仓，超阈值报错 |

第三类是要害。用 `skipna` 一把带过，它们会**无声蒸发**——零成本退出，是生存者偏差
的后门。而如果没有一个**正向**的停牌信号（只用"非退市即停牌"兜底），幽灵那一类恒为空、
`ghost_days` 恒为 0——**一道永远不会触发的告警比没有更危险，它给出的是虚假的安全感**。
所以缺 `is_halted` 时引擎**拒绝运行**，除非你显式选择降级口径。

### 七道闸门

每次评估自动亮七道：market beta、集中度、区间稳定性、成本临界倍数、多空平衡、
池子卫生、前视状态。**通过也打印数字**，没有判据时报 `NO-BASIS` 而不是 `PASS`——
空白绝不能在"干净"与"没查"之间有歧义。

其中**成本临界倍数**值得单说：报告 turnover 回答不了"这东西能不能投"，而
`pnl_gross / cost_total` 能——量纲恰好是"成本模型可以错多少倍"。

## 9. 贯穿全篇的一条原则：吵闹地失败

这套系统里绝大多数的设计选择，追到底都是同一句话：**宁可拒绝运行，也不要给一个
看着合理的错数。**

| 场景 | 静默的做法 | 这里的做法 |
|---|---|---|
| 缺停牌信号 | `ghost_days = 0`，看着很干净 | 拒绝运行，除非显式降级 |
| 定义改了 | 照常写入 | 指纹不符即拒绝 |
| 依赖还没更新 | 算半截 | `ed` 回退并出声 |
| 池外的票 | 带着值进下游 | 两端各夹一次 |
| yaml 键拼错 | 静默丢弃 | 报错并给最接近的候选 |
| 权重有空洞 | 跨洞仿真 | 拒绝，指出第一个洞在哪 |
| `Σ\|w\| = 0` | 除零得 NaN | 不做除法，记一笔诚实的空账 |
| 轴要改中间一天 | 覆盖 | append-only，拒绝 |

代价是引擎比"能跑就行"的版本啰嗦。收益是：**这套系统给出的每一个数，要么是对的，
要么它已经告诉你它可能不对。**

## 10. 组件地图

```
alpha_kit/                    纯引擎: 零数据定义、零口径配置
  core/    naming rank opspec panels project freshness axes store config
  runner/  node ctx ops preflight
  pnl/     simulate metrics report
  cli.py

repos/g_{user}/               研究仓库: 各自独立, 可以放在引擎仓库之外
  nodes/{node_dir}/*.yaml+py  节点
  regions/{region}.yaml       口径（每个 repo 一份, 内容必须一致）

pipeline/                     L1 → L2 → L3 摄入（将来独立成单独的 repo）
storage/                      L1 / L2 / L3
registry/                     security_id 注册表, append-only
```

17 个模块约 4500 行。每个模块只负责一件事，模块清单与各自的职责见
[`implementation.md`](implementation.md) §二。

引擎与研究仓库之间只有两个接触面：**L3 的引用名**，和 **region 文件**。
研究 repo 搬到别处照常工作，只要告诉引擎共享的 L3 在哪。

## 11. v0 的范围

已实现：L3 → L3 的统一 Node 内核、Zarr 存储、ops 链、零数据预检、precise 仿真与七道闸门、
逐节点血缘。

**不在 v0 内**：cache 与增量重算、摄入的 Node 化、alpha 池与晋升流程、
相关性去重、OOS 隔离。这些的设计见 [`roadmap.md`](roadmap.md)——那份文档里的东西
**都不存在**，不要照着实现。
